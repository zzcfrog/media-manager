# 后台任务显示与调度

更新日期：2026-11-07。整轮时间限制修复随1.0.22交付，安装与数据核验见[当次记录](local-update-1.0.22-2026-11-07.json)；当前本机1.0.24沿用该调度，见[最新交付](local-update-1.0.24-2026-11-07.json)。

Header原先覆盖5类任务：图片分析、视频分析、音频分析、ASR模型预加载、人脸识别。现有统一入口覆盖20类功能任务；模型下载按一个功能类别统计，内部区分本地大模型、人脸套装和SigLIP 2。压缩、抽帧、转写是分析的阶段，不重复计类。

普通图片读取、检索、菜单刷新和页面短请求不作为独立后台任务。长请求只在实际运行期间显示，SSE在关闭后释放计数。未完成的分类/关系任务按类别聚合全部状态，统计不受明细列表200项限制；完成、取消或过时记录不长期占据入口。

有字节数或真实阶段进度时显示相应进度；未知总量只显示进行中，不推算百分比。分类/关系分组提供暂停、继续或重试、停止；导入与同步可回到原详情，下载可打开对应设置。模型缺失、失败与手动暂停保持可见。读取状态失败保留已知任务并提供重试。

## 自动续跑

人脸识别、快速分类、本地补充和词库关系任务避让导入、AI分析及媒体播放。这是应用任务避让，不检测系统是否无人操作。共享后台推理锁仍串行协调分类与人物任务。

不再按每轮墙钟或Python历史峰值增量停机。前台任务出现时协作取消尚未提交的当前项，将自己持有的租约退回队列；分类让路不消耗重试次数。已完成项保留，前台结束后自动继续。正在执行的单次ONNX调用或模型HTTP请求不保证瞬间抢占，后续取消检查会拒绝迟到提交。

只恢复能明确识别为旧时间/内存预算导致暂停的任务；用户手动暂停、取消及模型停用不会被自动覆盖。模型/素材缺失保留等待，推理失败保留失败，需解决原因后重试。单次模型请求仍有独立超时，并不代表设置了整轮运行预算。

2026-11-07补齐人脸队列：移除仍残留的600秒固定轮次上限，包括前台让路及共享推理锁等待时的截止判断。队列持续处理到结束；前台结束后自动继续。启动worker时，仅在全局未手动暂停且人脸模型启用的情况下，恢复错误原因严格为「达到本轮时间预算，可继续」的历史暂停项；其他暂停、等待、失败、取消和已完成项均不因此重置。手动中断不再错误显示为时间预算到期。现有任务租约与心跳用于进程异常恢复，不限制整轮识别总时长。1.0.22安装后原预算暂停项已接续，后续版本保留该行为。

开启本地补充后，快速分类完成会排队补充；开启词库关系整理后，新增/编辑标签会排队，也可手动发起。开关停止后续自动排队，已有任务由Header控制。词库整理只处理文字关系，不重扫全部照片。

临时图片可释放，但ONNX会话、内存分配器缓存和本地大模型服务可能驻留；历史峰值不是当前内存，且不覆盖模型子进程，不能作为可靠总内存上限。旧预算设置键保留API兼容，但worker不再使用，也不在设置页展示。

## 接口与验证

`GET /api/background-tasks`只读返回辅助任务汇总和类别清单，不返回请求体、素材路径、凭据或原始错误。既有分析和人脸适配保留详细进度。`POST /api/background-tasks/control`限定四个分类/关系类别，撤销租约并执行模型停用门控；不会修改已生成的标签或人物结果。

验证包括合成队列、长请求生命周期、暂停/恢复/取消、200项以上计数和浏览器交互，记录见`build/background-tasks-settings-2026-11-06/`。没有调用真实付费接口或进行新一轮模型准确率/性能评测。
