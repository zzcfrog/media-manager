# 导入性能优化记录

日期：2026-10-22。状态：首版已随 1.0.10 打包并更新本地安装版，见 [本地升级验证](local-update-1.0.10-2026-10-22.json)。

## 实现范围

此前的批量导入在同一请求内逐文件串行处理；旧使用指南中的“3 个并发导入”与实现不一致。首版将耗时准备与数据库提交分开：每批最多 2 个准备线程，数据库由请求线程按输入顺序逐条提交，成功后才发送 SSE 成功事件。每个工作窗口最多 16 个文件，避免一次排队整个资料库；窗口间共用本次请求的线程池。多个导入请求各有自己的上限。

- 目录扫描同时收集普通媒体和加密音频提示，重复路径去重，减少重复遍历。
- 每个窗口用一次 ExifTool 调用读取图片/视频元数据；缺失的结果保留单文件回退。
- JPEG 的缩略图与相似度计算复用同一次完整解码；模型输入方向和变换保持一致。
- RAW 缩略图优先使用内嵌 JPEG，在内存中缩放；缺失或损坏时保留解码回退。旋转/镜像依据源文件 EXIF。RAW 相似度仍使用原来的完整 RAW 解码，没有用小缩略图替代特征输入。
- 本地 ResNet50 初始化加锁，避免两个准备线程重复创建会话。
- 导入结果使用现有 Quasar 虚拟滚动组件，卡片布局不变，完整结果可滚动查看。进度统计成功/跳过/失败；没有收到最终完成事件时显示中断提示。
- 每个文件记录元数据、预览、特征准备耗时（不记录模型密钥等配置）；批量 ExifTool 预读取时间不计入单文件 probe 时间，应结合整个请求计时。

## 数据和完成语义

原始文件保留原位置，不移动或复制；没有数据库结构迁移。开发和打包测试均使用隔离资料库及合成素材。1.0.10 本地升级已核对全部 13 张业务表、10,960 条素材、2 个工程、缩略图、模型配置及现有备份不变，并验证了新生成的升级快照。

首版没有“后台补齐”任务：缩略图/特征准备仍属于本次导入，既有格式回退和可选特征失败语义保留。文件处理中变化或离线会报告失败；一个文件失败不阻塞后续文件。写库失败时回滚本条记录并清理本条新缓存。连接关闭后取消待开始工作，等待已运行工作结束并丢弃未提交缓存，保留已经成功提交的文件；重新导入时自动跳过它们。强制刷新已有条目继续保留身份、标注和工程引用。

## 前后对照

环境：本机 SSD、隔离 SQLite 资料库，12 张 6000×4000 合成 JPEG（包含旋转 EXIF），4 段 1920×1080 合成视频。真实 ExifTool/FFmpeg 和本地 ResNet50，固定 CPU 提供程序；会话预热后各测三轮，源文件字节一致。旧流程由修改前保存的 importer.py 执行。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 三轮总耗时（秒） | 13.468 / 13.167 / 13.124 | 5.114 / 4.723 / 4.649 |
| 总耗时中位数 | 13.167 秒 | 4.723 秒 |
| 第一条成功通知中位数 | 1.047 秒 | 0.863 秒 |

中位总耗时缩短约 **64.1%**，吞吐约为原来的 **2.79 倍**。排除数据库生成 ID、缓存 UUID、导入时间等运行特定字段后，所有记录的元数据和相似度向量字节校验一致。原始测试数据和轮次结果保存在 [验证记录](import-performance-validation-2026-10-22.json)。

## 验证范围与限制

Python 完整回归、前端状态回归、桌面数据路径回归，以及隔离 Chromium 的真实导入和大量结果滚动已纳入验证。具体通过数量和浏览器错误结果见验证记录。

- 此数字不能直接外推到用户的移动硬盘、两三千个文件或混合 RAW 批次。机械盘的寻道、USB 接口和文件大小都可能改变收益。
- 真实相机 NEF/其他 RAW 的整体速度和色彩尚未实测；已验证内嵌 JPEG 路径、损坏/缺失回退、8 种 EXIF 方向。不能以合成 RAW 容器替身代替真实 RAW 性能结论。
- 验证沙箱中的 CoreML 临时编译目录不可用，性能对照固定 CPU；应用运行时仍保留原有 CoreML/CPU 选择。
- 未减少 RAW 相似度本身的计算量；后续若仍慢，再评估缓存复用或有明确状态和恢复机制的后台任务。
- 本次未调整音频波形/封面处理策略、视频编码方式、资料库布局或模型选择设置。
