# 本地图文分类速度实测 · 2026-10-30

本机 Apple M3 Max、48 GiB 内存、16 逻辑 CPU。从现有资料库只读抽取 96 张照片缓存与 32 张视频封面缓存，复制到隔离目录；没有读取原片。两款模型使用相同 100 个英文类别短描述，输入均为 224×224。英文描述可以配中文显示名称，本轮没有评估中文描述的分类准确率。

固定模型：`openai/clip-vit-base-patch32` 和 `google/siglip2-base-patch16-224`；版本、下载大小与 SHA256 见 JSON。大权重与上游 LFS SHA256 一致，推理阶段强制离线。正式应用仍为 1.0.14，未修改业务代码、资料库、已有模型或安装包。

## Apple GPU / CPU

以下为平均毫秒/张，包含缓存文件读取、解码、预处理、图片编码、100 标签匹配和 Top5 返回。GPU 为 PyTorch MPS FP32；批量列是吞吐摊销值，单批耗时应乘批大小。GPU 128 张、每种模式重复 3 轮；CPU 为同一集合均匀取 32 张、4 线程、1 轮。数据已预热，不包含模型加载。

| 模型 | GPU 逐张 | GPU 8 张/批摊销 | GPU 32 张/批摊销 | CPU 逐张 |
|---|---:|---:|---:|---:|
| CLIP ViT-B/32 | 9.17 | 3.54 | 2.99 | 19.37 |
| SigLIP 2 Base | 12.37 | 6.40 | 5.62 | 39.76 |

另测 FP16、纯编码/匹配、不含读图等分项及 p50/p95，详见 JSON。GPU 每批前后显式同步，避免把异步提交时间当作实际识别时间。

## 现用 ONNX Runtime / CoreML 验证

将两款模型的图片编码器导出为静态 batch=1 的 FP32 ONNX；CLIP 另测 batch=8。使用应用已有 ONNX Runtime，CoreML MLProgram / ALL，允许 CPU 回退。标签文字特征由同一固定模型预先缓存；这里没有导出文字编码器，尚不等于完整产品集成。ORT 匹配取 Top5，省略不改变排序的 softmax/sigmoid。

| 模型 | 纯编码及匹配 ms/张 | 含缓存读图 ms/张 | 与 PyTorch CPU 最低特征余弦 |
|---|---:|---:|---:|
| CLIP ViT-B/32 | 4.05 | 6.20 | 0.99999940 |
| SigLIP 2 Base | 6.91 | 8.76 | 0.99999940 |

CoreML profile 确认实际执行 CoreML 子图，同时有少量 CPU 节点；不能据此声称全部计算都在 ANE。PyTorch 分项的特征匹配 logits 与完整模型 forward 对照通过；ONNX 与同输入 CPU 特征数值对照通过。这些是实现数值核验，不是人工标注的语义准确率。

SigLIP 2 原始导出在 CoreML 编译时报 `Required param 'pad' is missing`：卷积使用 `auto_pad=VALID`。仅在隔离的 ONNX 副本中将它改成数学等价的显式零填充，然后重新做 CPU / CoreML 数值与速度验证。原始模型权重和生产代码未修改；不能把原始导出描述成开箱即用。

## 启动成本

| 模型 | CoreML 无模型缓存初始化 s | 复用缓存重建会话 s（ORT profile） | 首次批预测 s |
|---|---:|---:|---:|
| CLIP ViT-B/32 | 121.44 | 23.05 | 1.63 |
| SigLIP 2 Base | 133.31 | 26.44 | 1.00 |

首次编译与每张识别速度差别很大。接入时应在启用模型后后台预编译、持久缓存并保持会话常驻，不能每张图重新建会话。缓存模型也存在会话加载成本；不是“有缓存就立即启动”。[ONNX Runtime CoreML 缓存说明](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html)。

同一模型的图像特征已经缓存后，100 标签纯矩阵匹配与 Top5 提取非常快，JSON 中给出每轮 128 张的耗时；不含读取数据库特征、类别文字首次编码与模型加载。

## 适用范围

本轮证明这两款模型在本机具备毫秒级缓存预览分类速度，适合继续验证后台分类。没有测原片读取/RAW 解码、缩略图生成、EXIF、移动硬盘 I/O、资料库写入、导入并发争抢和完整视频抽帧，不能把这里的吞吐当作整批导入速度。

没有人工分类真值，不能据此决定谁更准确，也没有与本地 Omni 做同条件速度或准确率比较。准确率选型需要另一轮有标注的类别测试。

测试脚本、权重及私有原始时序位于 Git 忽略目录 `build/scene-speed-2026-10-30/`，报告只包含汇总。清理情况见对应 JSON 的 cleanup 字段。
