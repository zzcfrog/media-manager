# 批量标签操作

更新于2026-11-07，UI规范1.35。入口为`TaxonomyTools`，保留原有标签API，仅改变操作栏的呈现位置。

## 结构与使用

`筛选栏 → 标签按钮 → 标签操作弹层 → 目标标签 / 添加 / 移除与排除 / 分析与快速分类`

素材库、我的喜欢和人物相册使用同一个组件。智能分类与智能图集保持现有入口范围，不新增此按钮。按钮在AI分析左侧，标签72px、AI分析128px、高32px、间距8px。未选素材时整组选中操作不可见且不可聚焦，保留水平占位；不能用新增一整行的方式呈现批量操作。

| 接口 | 契约 |
| --- | --- |
| `gallery` prop | 当前图库，读取`selArr`和`allMediaItems`；通过原有`refreshAfterDetail()`刷新已变更标签 |
| `menuOpen` | 组件内部弹层状态；实际选择范围变化或离开页面时关闭 |
| `target` / `clearExclusion` | 目标标签与明确解除冲突排除的原有草稿 |
| 标签API | 保持`decisions`、`decisions/preview`、`apply`、`jobs/preview`、`jobs`原协议 |

在图库的筛选操作区挂载`<taxonomy-tools :gallery="this">`，由外层控制是否属于支持页面及选中组的可见性。不要再把组件放到`library-workspace`顶部，也不要把标签维护表单嵌进图库。

## 功能与状态

- 单选、多选显示同一入口；数量显示在弹层标题右侧。AI分析使用固定短名称，完整数量保留在Footer、可访问名称与提示中。
- 标签选择使用原分级选择器及名称/同义词搜索。选择目标不会立即保存，点击添加才提交当前范围。
- 未选目标时禁用添加、移除和排除。添加时可明确解除冲突排除，默认关闭。
- 移除直接标签和排除子树继续使用影响预览与明确确认；取消不改变标签。整理已有分析继续展示可用/跳过范围，无分析结果时不能排队。
- 正在请求时呈现loading和`aria-busy`并禁用重复提交；成功收起弹层，失败沿用可见错误通知，保留目标及重试入口。
- 切换页面、清空或改变所选素材时收起弹层。后台刷新产生相同ID数组时保留当前弹层。

## 外观与键盘

弹层336px，宽高受视口限制，必要时只在弹层内部滚动；使用主题表面、文字、控件圆角、阴影和8px组间距，不硬编码亮暗颜色。

触发器为原生按钮并提供`aria-haspopup="dialog"`、`aria-expanded`及可访问名称。Enter/Space打开；内层选择器的Escape只关闭内层，外层Escape关闭标签操作并返回触发器。按钮可用Tab到达且焦点可见，操作弹层不能触发图库的选择、删除和评分快捷键。

## 验证入口

使用`tests/people-browser-fixture.py`提供临时合成资料库，运行`PEOPLE_BROWSER_FIXTURE=<隔离JSON> node tests/tag-actions-browser.cjs`。场景覆盖真实添加/移除/排除及解除冲突、预览取消、后台任务请求契约、loading/失败重试、键盘及命名核查、页面切换和多种窗口/主题几何；模型任务在浏览器拦截，不执行真实推理。

源码：`frontend/js/taxonomy.js`、`frontend/js/gallery.js`、`frontend/css/taxonomy.css`。当前变更不改检查器、分类状态或人物操作范围。
