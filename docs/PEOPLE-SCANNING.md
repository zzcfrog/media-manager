## 按需下载

只有上方组合选择器使用统一模型列表，列出六个InsightFace套装、体积、已安装状态和下载按钮。下方三阶段没有独立选择或下载入口。组合下载使用完整官方ZIP并填入全部对应阶段，目的地为通用模型根目录的faces/子目录；已安装项自动绑定完整文件，不再新建custom组合。

组合下方不再保留重复的「下载套装」按钮。模型列表旁的下载打开确认弹窗：根目录只读，信息按钮说明可在「设置 → 通用」修改；子目录默认 `faces/套装ID`，可以更名为该命名空间下的单层文件夹。弹窗列出阶段、架构和实际文件名，Buffalo两项、Raccoon包含可选复核三项。目标已存在时拒绝下载并保留输入，不覆盖或静默换位置；取消不启动下载。已有外部ONNX仍可从各卡片选择。

来源为 [InsightFace 官方 model-zoo Release](https://github.com/deepinsight/insightface/releases/tag/model-zoo)，六个 ZIP 的体积和 SHA-256 按 2026-11-01 GitHub Release API 固定在 `backend/services/face_model_downloads.py`。哈希用于下载完整性，手动加载兼容文件不受此版本清单限制。公开权重许可见[官方说明](https://github.com/deepinsight/insightface/blob/master/python-package/docs/model_zoo.md#model-licenses)。

下载包先写入目标位置的私有临时目录，校验大小、SHA-256、ZIP 路径与重复文件，再对必需 ONNX 做实际接口试跑。仅保留检测/特征/可选复核以及包内的 manifest、许可文件；每次发布到新的套装子目录，绝不覆盖现有模型。失败或取消删除本次临时文件，不发布半成品；不提供断点续传。应用异常退出可能留下 `.luminisle-face-*` 临时目录，可在确认无活动下载后人工清理。

下载成功仅填入当前设置草稿，点击底部确认后才保存配置。若期间编辑了路径、切换了组合或关闭再打开弹窗，不会迟到覆盖；可从已安装列表重新选择或主动填入已下载模型。取消设置不会删除已完整下载的文件。根目录下载记录用相对文件及SHA-256保存，重启或模型目录迁移后能重新列出；保存的阶段模型ID从当前根目录解析。独立外部路径保持原样。下载和设置保存均不自动启动历史扫描。

接口：`POST /api/people/models/probe`（`stage,path`）；`GET /api/people/models/catalog` 返回 `base_directory` 和每套 `files`；`GET/POST /api/people/models/download` 接收 `profile`、可选 `stage,subdirectory`（stage仅供旧客户端兼容，新界面只提交整套），subdirectory限定 `faces/单层名称`。原 `directory` 参数保留供兼容，不与subdirectory混用，界面不再暴露。`POST /api/people/models/download/cancel` 接收 `id`。设置KV中的 `people_detector_model/recognizer_model/verifier_model` 为 `套装ID:阶段` 或空串（外部路径），没有新增数据库列。下载地址来自固定清单，不接受任意URL。

设置保存先比对读取时后台返回的字段集合。若开发窗口已加载新界面、后台仍为旧进程，草稿中的新字段可能被旧接口拒绝；此时提交前明确提示「人脸设置界面与后台版本不一致，请重启应用后再保存」，保留当前模型组合和路径，不发送部分设置或静默丢弃视频选项。需重启整个测试应用以同步前后端，单独刷新页面不会更新Python进程。

现有 Buffalo L / Raccoon S 的选型报告不自动推广为其他型号的精度或速度承诺：[官方模型列表](https://github.com/deepinsight/insightface/blob/master/python-package/docs/model_zoo.md)、[官方组件配置](https://github.com/deepinsight/insightface/blob/master/server/docs/user-guide.md#11-models-and-model-licenses)。

## 导入与历史扫描

- 导入请求提供布尔 `organize_people`，缺省为 false；勾选后可选择「仅图片／仅视频／两者识别」，对应 `people_media_type:image|video|all`，默认all，每次新开导入重置。单文件和批量接口均在执行前校验这两个字段，非法范围返回400。只对该次成功写入且符合范围的新照片/视频在同一事务登记后台任务；所有文件仍照常导入，音频不登记或启动人脸任务，不在导入线程加载模型。旧 `people_enabled` 值不再控制导入，也不在设置页显示。
- `POST /api/people/jobs` 支持 `selected` + `media_ids`、`folders` + 多个绝对路径、`all` + `confirm_all:true`；兼容旧单目录 `folder`。选目录表示递归其全部子目录，路径边界和 LIKE 通配符转义沿用素材库规则，同一素材只命中一次。
- 2026-11-05目录勾选联动修正：前端记录树中每层目录的勾选，父目录全选/取消递归作用于所有后代，部分子目录取消时父目录半选。提交时完整勾选的子树压缩到folders中的递归根；半选父目录自身被选择的直属素材使用新增direct_folders列表，避免父目录递归重新带入取消的子目录。两列表合计1～1000个范围，可只提供非空direct_folders与空folders；音频仍不进入识别队列。后端通过数据库中路径目录层级匹配直属文件，无需迁移表结构；旧folders、folder请求保持递归语义。
- GET /api/people/status新增supports_direct_folders:true。前端仅在部分勾选需要直属范围且后台声明支持时提交direct_folders；旧进程未返回该标志则提示重启应用，并保留勾选且不发起排队，避免旧接口静默忽略部分范围。仅完整子树的递归选择保持旧接口兼容。默认目录预选、收起/展开及迟到目录加载同步勾选，人工编辑后不被迟到的目录树覆盖。
- 2026-11-05起，开始弹窗只设置范围及跳过/重扫策略；整库选项仅指已导入素材的数据库记录，不遍历整块磁盘，文件夹树同样来自素材库。用户选择整库并点击开始即表示该范围，前端自动携带confirm_all:true兼容既有API，移除额外确认复选框。原素材、人工决定与跳过/重扫语义不变。
- 排队成功后关闭弹窗，Header共享后台任务入口显示人脸剩余队列与活动进度，并提供暂停、继续、重试、停止。照片/视频识别没有每次任务批次的准确百分比字段，因此使用活动态进度和真实剩余数，不混入历史完成数。开始弹窗及人物Footer不再展示任务控制；Header最多显示6个近期素材状态，失败信息按需提示。停止仍调用既有cancel操作，仅取消未完成任务，已完成结果和原文件不受影响。过期stale记录不计入活动队列，避免配置变更后的历史记录使Header始终显示未完成。
- `existing:skip`（默认）跳过当前素材版本已有 done/no_faces/quality_insufficient 的结果，即使模型配置已切换；素材输入版本变化后可再扫描。`rescan` 重新登记已完成素材，保留人工命名、合并与纠正；已排队/正在处理的任务不重复登记。失败/等待任务可重试。
- 返回 `queued/skipped/total`。明确的新人物与匹配自动归组；相似但不确定的归组、低质量且无法归属的脸进入待核对。人工命名独立于审核。

## 视频与事务

当前视频走「连续解码并按所选帧率取帧 → 检测与光流跟踪 → 轨迹内挑选清晰代表帧 → 身份识别 → 既有人物归组」。设置「人脸识别 → 视频人脸识别」提供「视频压缩」、检测帧率和每次出镜取样数。视频压缩只提供1080p／原片，默认1080p：按短边1080px等比缩小、不放大小视频；原片使用原始分辨率，两者均不再受1280px长边限制。分辨率与视频AI分析的引擎和`resolution/local_frames_res`独立，检测帧率仍提供1、2、3帧/秒、默认1帧/秒。旧 `people_max_frames` 仅兼容旧接口。

2026-11-07，独立视频压缩设置已随1.0.24更新本机。先在资料库副本及安装后的暂停状态核验48张原表和21565个既有文件，再按用户要求使用默认1080p继续2890项原暂停任务。其中594项视频任务已核验接续到1080p配置，原1101项等待任务、人工姓名和归属及0.50基准／0.45校准阈值保留；没有另起全量重扫。详见[本机更新记录](local-update-1.0.24-2026-11-07.json)。

`settings.video_resolution`与`PATCH /api/people/settings`使用字符串`1080p|original`，保存到既有settings表的`people_video_resolution`；缺省读1080p，非法值原子拒绝，无新表或新列。原片在内部工作请求中以`resolution:null`传递，复用进程时逐请求生效，不改变模型身份空间。确认保存、取消丢弃，老后台缺少字段时阻止写入并提示版本不一致。设置本身不新增扫描范围，不重扫已完成素材；已排队的视频在领取前按新配置重排，正在处理的视频切换后取消旧租约并重新排队，防止旧配置结果写入。暂停、等待、已完成及取消状态不因设置保存自动恢复；原暂停任务继续时沿用现有重排逻辑。照片历史配置键保留，不因新增视频分辨率选项失效。
