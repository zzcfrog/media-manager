# 全系统 UI 走查 · 2026-10-31

基准：[UI 规范 v1.0](UI-SPEC.md)。状态：**9 类确认问题已修复、隔离验证，并随 1.0.16 正式包更新本机。** 原始走查只新增报告；随后用户授权修复与安装，修复和发布结果见第 7、8 节。

当前图库骨架、主区域缝隙和新智能图集入口已较接近规范；主要遗留问题集中在 Quasar 与主题变量衔接、分段选中态、旧页面控件尺寸以及键盘操作。不能据此宣称全系统已经完成 UI 统一。

## 1. 范围与方法

- 使用当前工作区代码、三个独立合成资料库；图片、视频、音频、人物和工程均为测试数据。
- 浏览器为 Playwright Chromium。主矩阵覆盖 1600×900、1000×600 和四主题 × 明暗；专项脚本另覆盖 1280×800、1440×900。
- 主走查采集 126 个页面/外观状态，另对主题颜色、对比度、边框、键盘、菜单和向导补充复现。状态数是取样数量，不代表 126 项独立功能全部通过。
- 正常浏览、空态、错误/重试、离线缓存、主题切换、导航返回和弹窗取消结合现有回归检查。没有调用真实 AI、下载模型、修改原片时间或实际导出工程。
- SEO、移动端适配和公共网站的 canonical/sitemap 等不适用于本桌面应用，未作为缺陷条件。

## 2. 原始问题清单（修复前）

本节保留修复前的触发条件和测量结论，代码链接指向当前对应实现位置；不要把历史数值当作修复后状态。

优先级是本轮 UI 整理顺序：P1 为关键状态可读性问题；P2 为跨页面一致性或操作缺口；P3 为局部视觉/文案统一。它们不是数据安全等级。

### U01 · 框架品牌色未随主题同步

**触发：** 任选主题，打开设置 → 视频分析；观察当前页签、开关与底部「确定」，或进入工作台观察「构思」。八种外观均可复现。

**证据：** 温润墨玉暗色的主题强调色是 `#8bceba`，但 `body` 内联 `--q-primary` 与 `--q-accent` 仍为 `#007aff`。设置「确定」的背景始终为 `rgb(0,122,255)`，文字却使用各主题的 `--on-accent`。八种外观的文字对比度为 **2.70–4.02:1**，都低于规范给小号文字设定的 4.5:1 目标。月光瓷釉暗色最低，约 2.70:1。

**原因/位置：** [框架品牌初始化](../frontend/index.html#L1855)写死主色和强调色；[主题变量映射](../frontend/css/themes.css#L6)没有覆盖框架写入的内联值。若只修改单个按钮 CSS，其他开关、页签和通用弹窗仍会遗漏。

**建议：** 在统一主题入口同步 Quasar 的实际品牌变量，并统一背景与反差文字的来源。对应规范 §4、§5、§7。

### U02 · 分段控件使用浅底片配反差文字

**触发：** 设置中的云端/本地引擎切换；查找重复或查找相似中的档位切换。

**证据：** 已选按钮仍带 `.bg-primary`，其背景被滑动分段规则设为透明，选中底片实际是 14% 强调色叠在控件底色上；高优先级文字规则却强制使用 `--on-accent`。亮色出现近白字配浅底，暗色出现深字配暗底。引擎按钮按平面底色合成测得八种外观约 **1.44–1.52:1**。查重/相似的选中档位可见同样的问题。图库文件类型和 Any/All 已有专门的实色底片规则，不属于这一缺陷。

**原因/位置：** [分段底片与文字规则](../frontend/css/native.css#L360)、[通用 bg-primary 反差文字规则](../frontend/css/themes.css#L98)。

**建议：** 明确统一的两种搭配：实色强调底片 + 反差文字，或浅强调底片 + 强调色文字；同时消除框架旧选中 class 对共用组件的覆盖。修好 U01 不会自动修复这里的浅底片搭配。对应规范 §7、§9.2、§13。

### U03 · 暗色 outlined 字段仍是白灰描边

**触发：** 墨玉或瓷釉暗色 → 标签树维护 → 选中标签，观察标准名称、定义、识别描述等输入框。

**证据：** 多个未聚焦字段的 `::before` 仍为 `1px solid rgba(255,255,255,.6)`。墨玉/瓷釉本应使用的 `--border2` 分别是 `#3e695d`、`#516a87`。它们不是主题定义的低对比边缘。

**原因/位置：** `TaxonomyPage` 的 outlined 表单位于 [taxonomy.js](../frontend/js/taxonomy.js#L982)；[原生表单样式](../frontend/css/native.css#L343)主要处理 filled 字段与弹窗底边，没有完整接管各类 outlined 字段的四边。

**建议：** 统一默认、悬浮、聚焦、错误、禁用等边框状态，保留错误语义色，不逐页添加孤立白色覆盖。对应规范 §4、§5、§7。

### U04 · 人物页工具栏的几何与字号漂移

**触发：** 1000×600 → 人物总览。常规窗口也存在同类差异。

**证据：** 搜索/排序字段高 **40px**，视图、新增人物与整理按钮约 **25.11px**。搜索字段外层字号为 14px，窄窗口按钮使用 11px；工具栏有 7px 顶内边距，字段上沿为 y=63，而侧栏面板和图库控件上沿基准为 y=56。当前宽度下工具栏组间 gap 为 5px。

**原因/位置：** [人物样式基础及窄窗覆盖](../frontend/css/people.css#L2)、[人物工具栏](../frontend/js/people.js#L93)。它使用独立的旧密度规则，没有复用图库的 32px/12px 控件基准。

**建议：** 先统一同一工具栏的外高、字级和上沿，再保留人物专有操作。人物卡片属于人物实体卡片，不能据此机械要求它与照片缩略图使用完全相同的卡片内容排版。对应规范 §3、§6、§7。

### U05 · 图库筛选的键盘/名称不完整

**触发：** 使用 Tab 浏览图库筛选栏，或查看该区域的浏览器可访问树。

**证据：** 喜欢、分析状态、搜索提交三个图标按钮在可访问树中只有 `button`，没有名称；tooltip 没有形成可访问名称。五个评分星和五个颜色筛选是可点击 `span`，没有 `tabindex`、角色或键盘处理，可访问树只把星号当作文本。它们的快捷评分功能操作选中素材，不能替代键盘改变筛选条件。

**位置：** [喜欢/分析筛选](../frontend/js/gallery.js#L210)、[评分/颜色筛选](../frontend/js/gallery.js#L227)、[搜索提交](../frontend/js/gallery.js#L239)。

**建议：** 使用可聚焦的按钮或相应选择组件，补充本地化名称与状态，并核对 Enter/Space、筛选三态的语义。对应规范 §7.2、§9。

### U06 · 右键菜单缺少 Escape 退出

**触发：** 在任意素材卡片上右键 → 按 Escape。

**证据：** 在两个独立浏览器复现后 `.ctx-menu-popup` 仍然存在。点击外部可以关闭，Escape 没有关闭；菜单条目的实际角色是 `listitem`。本轮只将已复现的 Escape 缺口列为确认问题，其他方向键行为需随修复补测。

**位置：** [自绘菜单模板](../frontend/js/gallery.js#L703)、[打开与关闭处理](../frontend/js/gallery.js#L1842)、[图库键盘处理](../frontend/js/gallery.js#L1884)。

**建议：** 先让菜单拥有当前键盘上下文，支持 Escape 关闭与合理焦点恢复，再核对方向键和 Enter 不会穿透操作背后图库；与智能图集的标准菜单行为统一。对应规范 §7.2。

### U07 · 图库外部筛选按钮没有统一外高

**触发：** 素材库常规窗口，与文件类型/视图组合组对比。

**证据：** 文件类型组外高 32px，喜欢与分析按钮为 **24px**，检查器开关为 **30px**。它们是筛选栏外部操作，不是已明确允许为 28px 的组内按钮。Header 38px 外框内的 30px 工具按钮是另一种角色，不计入本项。

**位置：** [喜欢/分析 size=sm](../frontend/js/gallery.js#L211)、[检查器开关](../frontend/js/gallery.js#L263)、[filter-actions 尺寸](../frontend/css/native.css#L149)。

**建议：** 对齐独立操作按钮的 32px 点击外框；保持内部图形的光学大小，不通过放大所有图标补齐外框。对应规范 §1、§7。

### U08 · 独立筛选组间距仍有 10px / 6px

**触发：** 1600×900 打开素材库；对比筛选栏左右各组。

**证据：** 左侧 `.filter-controls` gap 为 **10px**，右侧 `.filter-display-controls` 为 **6px**；窄布局的部分覆盖又使用 8px。文件类型与高级筛选之间已是 8px，主素材区缝隙也已是 8px。本项不把组合控件内部的 2px、图标与文字的 4–6px 当作问题。

**位置：** [左组间距](../frontend/css/native.css#L146)、[右组间距](../frontend/css/taxonomy.css#L129)。

**建议：** 独立组之间引用 `--workspace-gap`，保留内部小间距的明确角色。对应规范 §3.2、§15.1。

### U09 · 导出名称弹窗混用英文取消文案

**触发：** 中文界面 → 工作台 → 导出工程；不提交导出。

**证据：** 标题、描述和确认按钮均为中文，取消按钮显示 **Cancel**。本轮确认范围是工程导出弹窗，未把所有框架弹窗都推定为已复现。

**位置：** [exportProject 的通用 Dialog](../frontend/js/workbench.js#L2321)使用 `cancel:true`，取消文案依赖未同步的框架默认语言。

**建议：** 给通用弹窗显式传本地化文案，或同步配置 Quasar 语言包；业务语言、HTML 语言和框架弹窗语言分开验证。英语切换后 HTML 的 `lang=en-US` 本轮是正确的，不属于缺陷。对应规范 §6、§7。

## 3. 已达标或本轮未见明显问题的部分

- 1600×900 实测：侧栏面板右缘 x=248、图库左缘 x=256；筛选与侧栏上沿 y=56；素材与检查器上沿 y=96；网格列/行 gap 8px。
- 图库的 8px 稳定滚动 gutter 已包含在右侧缝隙中：内容右缘 x=1296、检查器左缘 x=1304；检查器右缘 x=1592、窗口右缘 x=1600。没有重复叠加 padding。
- Footer 左基线 x=256，创建图集按钮、数量、摘要及缩放保持可用。Header 导入按钮与工具组外高均为 38px。
- 四视图面积图标、两列瀑布流图形、Any/All 与子标签开关、滑动选中底片均通过现有图库控件检查；文件类型与高级筛选的 8px 邻接保持。
- 图片/视频/音频高级面板外边距与内边距已统一到现有 8px 基准。组标题与字段的 2px 内部间隔属于内部排版，不误报为外部缝隙问题。
- 智能图集的可见添加按钮、主题边框、侧栏四角星及创建/重命名/删除流程通过；没有再使用侧栏同款纯图标充当创建动作。
- 智能分类与维护入口保持一列侧栏；树的外层滚动、维护集中在主区、分级标签与 footer 回显通过布局回归。
- 人物命名、纠正/撤销、组合图库、详情返回与错误重试等 17 组回归通过。
- 创作第 2–6 步均能在 1000×600 浏览并进入下一步，footer 位于窗口内；到生成前停止。导出弹窗能够正常取消。
- 正常路径没有捕获到 JavaScript 页面异常。蓝色合成缩略图、播放器黑底及专业时间线颜色不是主题失效的证据。

原文件夹脚本的 `.app-sidebar .folder-tree` 同时匹配目录树与分类树，产生 strict-mode 错误；本轮没有改动原测试。临时审计副本限定到包含 `.folder-tree-item[data-path]` 的树后通过。该脚本定位需在后续测试维护中同步，不计为产品 UI 缺陷。

主题脚本首轮受综合样本中故意缺失的缩略图 404 干扰；基础 fixture 中另一次几何取样曾碰到过渡时机，复核运行通过 7 组。未据这些单次失败虚报主题切换会重排页面。

综合 fixture 混合了两套维数的合成向量，查重曾返回 500；使用同维度的基础 fixture 正常得到一组重复结果。缺失音频封面 404 是既有波形回退，离线缩略图 404 是预设样本；切页终止音频请求的 `ERR_ABORTED` 也未作为故障上报。

## 5. 待进一步验证或设计取舍

- 全局 CSS 的 2px 焦点 outline 会被 Quasar `no-outline !important` 抑制，但当前按钮仍有 opacity=0.22 的原生 focus helper；**不能直接认定全站没有焦点反馈**。其在各种材质/高对比偏好下的辨认度，留待专门的键盘/对比度检查。
- 人物总览的艺术标题、较宽卡片间距是否进一步压缩，属于设计取舍；本轮没有把人物实体卡片强行视为普通媒体缩略图。
- 所有操作系统原生选择器、生产 Electron 安装包/IPC、多个显示器/缩放率、长时间导入/分析进度、实际 AI 生成、真实原片读写及导出结果本轮没有全量实测。
- 本轮不是完整 WCAG 审计、性能基准或业务逻辑全面测试。表单的边界保存与数据安全沿用既有专项测试，不能从本次视觉取样推定全部通过。

## 6. 建议修复顺序与证据

1. 同一轮处理 U01/U02/U03：先打通主题与框架，再验证选中态、普通/聚焦/错误表单边缘，逐项核对八种外观。
2. 处理 U04/U07/U08：统一人物与图库工具栏的尺寸和独立组间距，保留专业画布和不同内容卡片的必要差异。
3. 处理 U05/U06/U09：补齐筛选语义、菜单键盘闭环及框架弹窗文案；使用实际键盘和中英文复查。

本机可复现证据位于已忽略的 `build/ui-audit-2026-10-31/`，没有将截图或一次性 JSON 放回 docs：

- `sweep.json`：126 个取样状态、控件/区域几何与请求记录。
- `followup.json`：八种外观的颜色与分段对比度、outlined 边框、人物控件及弹窗。
- `interactions.json`：可访问树、菜单退出、正常查重/相似、创建时间、语言与向导检查。
